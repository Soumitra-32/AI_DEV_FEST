# Deployment Guide — Shonchoy Copilot

## 1. Architecture (what runs where)

```
Browser → Vercel (Next.js static + SSR, api.ts)
              ↓ NEXT_PUBLIC_API_URL
         Render free tier (uvicorn backend.app.main:app, $PORT)
              ↓ SQLite file (regenerated each deploy, deterministic seeds)
         LightGBM / IsolationForest / LogReg artifacts (tracked in git)
```

No Postgres, no queue, no cache, no Docker in production. Render builds from
source (`render.yaml`); Vercel builds `web/` from source. SQLite lives on
Render's ephemeral disk and is regenerated by the build command, so data is
identical on every deploy (fixed seeds in `backend/data/config.yaml`).

## 2. Environment setup

| Variable | Local (`AI_DEV_FEST/.env`, gitignored) | Production (Render dashboard → Environment) |
|---|---|---|
| `DEMO_AUTH_TOKEN` | any local secret | dashboard secret, then match Vercel's `NEXT_PUBLIC_DEMO_TOKEN` |
| `CORS_ORIGINS` | localhost defaults | must include the Vercel domain |
| `LLM_API_KEY` (+ backups) | optional; empty = template mode | optional, same semantics |
| `LLM_TIMEOUT_SECONDS` | 8 recommended | 8 recommended |
| `FEATURE_*` | all true locally | all true unless hiding a page |

Web (`web/.env.local`, gitignored): `NEXT_PUBLIC_API_URL` (local:
`http://localhost:8000`, Vercel: the Render URL), `NEXT_PUBLIC_DEMO_TOKEN`
(must equal the API's token). Never commit keys — `.gitignore` covers
`.env`, `.env.local`, `*.db`, `*.jsonl`, venvs.

## 3. CI (`.github/workflows/ci.yml`, runs on every push/PR)

1. **backend-test** — Python 3.12, install, full `pytest` (no keys in CI, so the
   deterministic template path runs in minutes).
2. **frontend-build** — Node 20, `npm ci`, `npm run build`.
3. **smoke** — generates data, boots uvicorn, curls `/health`, `/me`,
   `/metrics`, `/parse-goal`. Fails the pipeline if any is non-200.
4. **docker-build** — builds `backend/Dockerfile`, runs it, curls `/health`.

## 4. CD (manual gate: Render auto-deploys `dev`, Vercel auto-deploys on push)

1. Push to `dev` → CI must be green first (check Actions tab).
2. Render rebuilds: pip install → `generate_data.py` → `seed_demo_user.py` → uvicorn on `$PORT`.
3. Vercel rebuilds `web/` with its env vars.
4. Verify: `<render-url>/health` → `"status": "ok"`; open the Vercel URL and run one voice sentence end to end.

## 5. Local verification (the full gate before pushing)

```bash
backend/.venv/bin/python -m pytest backend/tests -q
backend/.venv/bin/python backend/scripts/security_probe.py   # server up first
cd web && npm run build
docker compose up --build    # http://localhost:3000, API on :8000
```

## 6. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `ECONNREFUSED :8000` | API not running | start uvicorn (see §5) |
| `/health` degraded / 503 on data routes | missing `shonchoy.db` | `python backend/scripts/generate_data.py` |
| 401/403 from web | token mismatch | align `.env` ↔ `web/.env.local` |
| Chat slow (~1 min), `source: template` | LLM quotas burned/keys absent | expected fallback; check keys + quotas |
| 429 on chat | 20 req/min limit working as designed | wait 60s |
| `GET /v1/models 404` in logs | something probing for an OpenAI endpoint | harmless noise, ignore |
| 500s under parallel clicks | fixed via `check_same_thread=False` (`deps.py`); if it returns, check the log traceback first | — |

## 7. Manual actions (cannot be automated from here)

1. **Rotate the demo token**: it is currently committed in `render.yaml`. Generate a new one, set it in Render dashboard → Environment (`DEMO_AUTH_TOKEN`) AND Vercel (`NEXT_PUBLIC_DEMO_TOKEN`), then replace the yaml value with a placeholder.
2. **Tighten CORS after the demo**: `allow_origin_regex` currently accepts any http(s) origin (helps on demo networks). Restrict to the Vercel domain when judging ends.
3. **Morning-of-demo**: verify 3 LLM model IDs, key quotas, `/health: ok`, one spoken sentence → plan computes, backup video ready.
